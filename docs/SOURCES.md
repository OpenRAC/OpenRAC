# Where the code comes from

OpenRAC does not hold the decompiled games itself. Each game is decompiled in a repository of its
own (a "decomp"), and OpenRAC includes it as a git submodule, pinned to one commit. This page
says what is under `games/`, and how to set it up, keep it current and change it.
[CREDITS.md](../CREDITS.md) lists the people behind each decomp.

## What's in games/

```
games/<game>/
  README.md            the game, its versions, which decomp each comes from, where the port's code is
  game.json            the discs, their checksums, which decomp each version is built from, its pin
  decomp/              our decomp of the game (git submodule): every version of it
  decomp-patches/      OpenRAC-only changes to decomp/
    NNNN-<what>.patch    one change each, its reason in the patch's message, applied in order
    files/               OpenRAC's own files, copied into decomp/ at the same path
    README.md            the list of patches and files, each with its reason
```

Ratchet & Clank (rac1) also has `ntsc-decomp/` and `ntsc-decomp-patches/`: the third-party NTSC
decomp of the North American release, kept apart from ours.

The pin is the commit the submodule is checked out at. game.json records it too, with every
version built from that decomp (top-level `"decomp"`, and each version's `"source"`), and the two
must agree. Nothing is ever committed inside a decomp folder: OpenRAC's changes are the patches.

Commands below name a decomp by its folder under `games/` (`rac1/decomp`, `rac1/ntsc-decomp`), or
by any version built from it (`rac1/pal` is `rac1/decomp`).

## First setup

```sh
git clone https://github.com/OpenRAC/OpenRAC.git && cd OpenRAC
python3 tools/sources.py init
```

`init` checks out every decomp at its pin and applies its patches.

## After a pull

```sh
git pull
python3 tools/sources.py init
```

Run `init` after every pull: a pull can move a pin or change a patch, and `init` brings every
decomp folder back in line. `python3 tools/sources.py status` shows where each one is.

## Changing a decomp

A match, a name, a build fix: anything that belongs to the decompilation itself goes to the
decomp's own repository as a pull request (the table above links each one). Once it is merged
there, bump the pin here (next section) to bring it into OpenRAC.

Only a change OpenRAC needs and the decomp does not (C that only the port relies on, a path for
OpenRAC's layout) is a patch here (below).

## Working in a decomp

A decomp with no patches is checked out on its main branch (game.json `"branch"`), at the pin:
`init` and `update` put it there. To change it:

1. In `games/<game>/decomp`, branch off its main branch, commit, push and open a pull request to
   the decomp's own repository.
2. Once it is merged there, switch the submodule back to its main branch and pull.
3. In OpenRAC, `python3 tools/sources.py update <game>/decomp` and open a pull request with the
   new pin and the port's regenerated tables (next section).

A decomp with patches stays detached at the pin, since its patches are changes in its worktree,
not commits on its branch.

## Bumping a pin

```sh
python3 tools/sources.py update rac3/decomp            # to the tip of its branch
python3 tools/sources.py update rac3/decomp <commit>   # or to one commit
```

`update` moves the submodule, rebases the patches onto the new commit and writes the commit into
game.json. On a conflict, fix it in the decomp folder, run `git rebase --continue`, then
`python3 tools/sources.py save rac3/decomp`.

The port reads each decomp at its pin, and some of its tables are made from that commit (hostgen's
configuration and tables, release names, asm interfaces, Windows exports, all under
`port/game/<game>*`). Regenerate them in the same pull request, then commit the decomp folder,
its patches folder, game.json and the port's tables together, as `chore(import)`. Check the new
commit against the [sourcing policy](policy/SOURCING.md).

CI runs `python3 tools/sources.py check --since <base>`. It fails when a pin and game.json
disagree, or when a pin moves without any change under `port/game/<game>*`. Run it yourself with:

```sh
python3 tools/sources.py check --since origin/develop
```

## Changing a patch

```sh
python3 tools/sources.py edit rac1/decomp   # the patches become commits in games/rac1/decomp
cd games/rac1/decomp                         # commit, amend or rebase as usual: one commit = one patch
cd ../../..
python3 tools/sources.py save rac1/decomp   # the commits become patches again
```

Each commit's message is the patch's reason; `save` also rewrites the list in the patches
folder's README.md. Commit the patches folder. To add a file of OpenRAC's own, put it under
`decomp-patches/files/` at the path it takes in the decomp, run
`python3 tools/sources.py apply rac1/decomp`, and say why in the README.

`python3 tools/sources.py unapply rac1/decomp` takes the patches out again, leaving the decomp as
its repository has it.

## Other projects OpenRAC builds on

These are credited where their work is used, and in
[THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md):

- [ReRAC](https://github.com/re-rac/rerac) (ISC): the moby, collision and
  animation formats in the editor, and function notes in rac1/pal.
- [Wrench](https://github.com/chaoticgd/wrench) (GPL-3.0-or-later): asset
  formats, read for the editor; the tool rac4 uses to unpack discs.
- splat, spimdisasm, objdiff, asm-differ, decomp-permuter, m2c and wibo:
  the decompilation tooling the projects use; none is vendored here.
